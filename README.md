# qr-viewer

موقع لرفع الملفات وتوليد باركود دائم لكل ملف — الرابط والباركود يفضلوا شغالين حتى لو استُبدلت الصورة لاحقًا، ومفيش حذف نهائي، استبدال فقط.

## الفكرة
- كل ملف مرفوع بياخد `id` عشوائي ثابت. الباركود بيشاور دايمًا على `index.html?id=<id>`.
- لما تستبدل صورة، الملف الجديد بيترفع على نفس الـ `id`، فالرابط والباركود المطبوع فعليًا **ما بيتأثروش**.
- مفيش زرار حذف يدوي في اللوحة، والحذف ممنوع على مستوى قاعدة البيانات نفسها لأي حد مسجل دخول أو لأ (RLS policies، شوف `schema.sql`).
- الباركودات القديمة (بصيغة `index.html?file=اسم_الملف`) لسه شغالة عادي — الصفحة بتدعم الطريقتين.

### صلاحية الباركود والتجديد
- كل باركود صلاحيته **سنة** من تاريخ رفعه (`starts_at` / `expires_at`).
- في لوحة التحكم، كل ملف بيظهر بشارة حالة: **نشط** (أكتر من 30 يوم متبقي) / **تنتهي قريبًا** (30 يوم أو أقل) / **منتهية**، مع زرار **"تجديد لسنة"** بيمد الصلاحية سنة كاملة من وقت الضغط بدون ما يغيّر الرابط أو الملف.
- لو الملف فضل منتهي بدون تجديد لمدة **30 يوم إضافية** (فترة سماح)، بيتشال تلقائيًا (السجل + الملف من الـ storage) عن طريق Job مجدول (`pg_cron`) — مش عن طريق زرار حذف يدوي، فمبدأ "بدون حذف نهائي يدوي" فضل قايم.
- الرابط `index.html?id=<id>` بيفضل شغال عاديًا طول فترة السماح، لحد ما يتحذف فعليًا.

## التقنية
موقع ثابت بالكامل (HTML/JS بدون build step)، مستضاف على GitHub Pages، ومربوط بـ [Supabase](https://supabase.com) (قاعدة بيانات + تخزين ملفات + تسجيل دخول) عبر الـ JS SDK مباشرة من المتصفح.

## خطوات الإعداد (مرة واحدة)

1. **أنشئ مشروع Supabase** جديد مجاني من [supabase.com](https://supabase.com).

2. **شغّل `schema.sql`**: افتح Supabase Dashboard -> SQL Editor -> الصق محتوى ملف [`schema.sql`](schema.sql) وشغّله. ده بينشئ جدول `qr_files` مع صلاحيات RLS (قراءة عامة، إضافة/تعديل للمسجلين دخول فقط، بدون حذف نهائي).

3. **أنشئ الـ Storage bucket**: من تبويب Storage -> New bucket -> اسمه `qr-files` بالظبط -> فعّل "Public bucket". بعدين من تبويب Policies بتاع الـ bucket ضيف:
   - Policy قراءة (SELECT) للجميع
   - Policy رفع (INSERT) وتحديث (UPDATE) للـ authenticated role فقط
   - **بدون** أي policy لـ DELETE

4. **أنشئ مستخدم الأدمن**: من Authentication -> Users -> Add user -> حدد إيميل وباسورد. ده اللي هتسجل بيه دخول في `admin.html`.

5. **املأ `supabase-config.js`**: خد الـ Project URL والـ anon public key من Project Settings -> API، وحطهم في [`supabase-config.js`](supabase-config.js).

6. **فعّل الحذف التلقائي بعد فترة السماح** (اختياري بس مهم عشان "التجديد أو الحذف الأوتوماتيك" يشتغل فعليًا):
   - تأكد إن extensions `pg_cron` و `pg_net` متفعّلة (السطرين الأولانيين في `schema.sql` بيعملوا كده، أو من Database -> Extensions يدويًا لو حصل خطأ صلاحيات).
   - شغّل في SQL Editor (بعد ما تحط قيمك الحقيقية):
     ```sql
     alter database postgres set app.settings.supabase_url = 'https://YOUR-PROJECT-REF.supabase.co';
     alter database postgres set app.settings.service_role_key = 'YOUR-SERVICE-ROLE-KEY';
     ```
   - الـ service_role key ده سري جدًا — بيتخزن كإعداد داخل الداتابيز بس، وميتحطش في أي ملف من ملفات الموقع.
   - من غير الخطوة دي، التجديد هيفضل شغال عادي من اللوحة، بس الحذف التلقائي للملفات المنتهية مش هيشتغل.

7. **ارفع المشروع على GitHub Pages** (الدومين الحالي `taim.best` معرّف في [`CNAME`](CNAME)).

## الاستخدام
- `admin.html`: سجّل دخول برسالة الأدمن، ارفع ملف جديد فيتولد ID ثابت + رابط + باركود، أو استبدل صورة موجودة من قائمة "الملفات الحالية".
- `index.html?id=<id>`: صفحة العرض — بتفتح تلقائيًا من الباركود.
